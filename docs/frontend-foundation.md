# Frontend foundation

Step 26 superseded the temporary shell with the deliberate product interface
documented in [Application UI](application-ui.md). The technical MapLibre,
static-delivery, and performance notes remain useful implementation context.

Step 25 established the technical frontend shell and Step 26 completed the
product UX layer without changing the static delivery contract. Step 27 added
the preset-aware candidate shortlist and direct candidate navigation.

## Stack and versions

- Vite `8.3.0`
- React `19.3.0` and React DOM `19.3.0`
- TypeScript `6.0.3`
- MapLibre GL JS `6.9.0`
- npm lockfile: `web/package-lock.json`, generated by npm `11.12.1`
- Node.js validation runtime: `v24.15.0`

The app lives in `web/`. `src/App.tsx` owns shared application state,
`src/components/` owns the product panels, `src/map/` owns MapLibre setup and
technical interaction, and `src/data/` contains the narrow delivery contract.

## MapLibre and basemap

`maplibre-gl` is imported directly. The v6 ESM worker is configured in
`src/map/mapConfig.ts` using the Vite URL import and `setWorkerUrl()`:

```ts
import { setWorkerUrl } from "maplibre-gl";
import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url";

setWorkerUrl(workerUrl);
```

The no-key basemap is OpenFreeMap Positron:
`https://tiles.openfreemap.org/styles/positron`. The URL is isolated in
`BASEMAP_STYLE_URL`; no hosting-provider configuration is coupled to it.
MapLibre's attribution control remains enabled, and the OpenFreeMap style
provides its required attribution. The official OpenFreeMap quick-start was
verified for the supported style endpoint before implementation.

## Static data boundary

`web/scripts/sync-data.mjs` is the only frontend-to-analysis data boundary. It
copies:

| Source | Ignored destination |
| --- | --- |
| `data/processed/delivery/candidates.geojson` | `web/public/data/candidates.geojson` |
| `data/processed/delivery/candidates.metadata.json` | `web/public/data/candidates.metadata.json` |
| `data/processed/delivery/candidate_shortlists.json` | `web/public/data/candidate_shortlists.json` |
| `data/processed/prioritization/presets.json` | `web/public/data/presets.json` |

The script fails clearly if required delivery artifacts are absent and prints
the Python delivery-generation command. For the candidate GeoJSON it checks
source size against metadata, copies bytes exactly, checks destination size,
and checks the metadata SHA-256 when present. The current sync result is:

- metadata: 17,283 bytes;
- candidate shortlist: 127,871 bytes;

  `1b7c7539750eb5c49d772d2c90d23a67bcbf73a83b50ae458c1cd10972ef2497`;

The copied assets remain untracked. `web/public/data/.gitkeep` is retained;

## Candidate map

The app fetches only the small metadata JSON in React. MapLibre owns the full
GeoJSON directly from `/data/candidates.geojson` through one source named
`candidates`; the app does not retain a second parsed copy and does not create
one source per preset. Existing feature-level IDs are used as the source
feature IDs, with no `generateId`.

The initial view fits `bbox_epsg_4326` from the delivery metadata with modest
padding. The layer stack contains an active-preset fill, subtle candidate
boundaries, a feature-state hover outline, and a property-filtered selected
outline. The fill styling is
isolated in `src/map/candidateLayers.ts` and uses a restrained interpolated
ramp over the selected precomputed score field. Preset switching changes the
paint expression without replacing the source.

Pointer movement uses MapLibre feature-state and clears only the prior
hovered feature. A click is handed to the React selected-candidate inspector;
the selected outline is updated with a lightweight `hex_id` source-property
filter. Navigation,
compass, scale, and attribution controls are enabled; pitch and bearing are
zero, and there is no terrain.

Metadata failures and MapLibre initialization/source/worker/WebGL failures are
shown as concise visible error states. MapLibre errors are categorized as
candidate-data, WebGL/worker, or basemap/style errors. Expected transient tile
errors are not continuously logged.

## Development instrumentation

`src/map/performance.ts` records development-only timing for:

- map initialization start;
- map load;
- candidate source requested and added;
- candidate source fully loaded;
- first idle after the candidate source/layers are present;
- `mapInitToLoadMs`, `candidateSourceLoadMs`,
  `candidateSourceToIdleMs`, and `totalCandidateReadyMs`;
- same-origin `PerformanceResourceTiming` fields when available:
  `transferSize`, `encodedBodySize`, `decodedBodySize`, and `duration`.

The result is printed once as `Candidate map performance` in development and
is available as `window.__candidateMapPerformance` for local inspection. The
frontend does not recount the GeoJSON in React; the expected full count comes
from the validated delivery metadata and audit.

Real-browser visual review was completed externally for the approved Step 27

assumes normal HTTP compression on the eventual static host.

The build reports a non-fatal warning that the primary JS chunk exceeds Vite's
500 kB advisory threshold. No bundle-splitting optimization is introduced
solely to remove the warning.

## Architecture conclusion

The real static assets build and serve cleanly, the full source remains a
single simple GeoJSON asset, and no current evidence requires PMTiles. The
deployment-provider choice and host-level compression remain open production
decisions; the MVP model and interface are otherwise development-complete.
